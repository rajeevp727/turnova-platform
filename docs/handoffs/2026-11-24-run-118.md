## Run 118 implementation

Audit finding: read-only Cosmos awaits in `CosmosDriverRideReservationStore` and `CosmosRiderActiveBookingReservationStore` checked cancellation after successful responses but did not consistently give caller cancellation precedence when the provider failed concurrently.

Implemented:
- Guard all five Driver reservation point-read awaits.
- Guard all four Rider active-booking reservation point-read awaits.
- Guard the Driver multi-Driver query-page await.
- Preserve existing 404 mapping when the caller has not cancelled, identity validation, ETag conditions, transactional batch/audit atomicity, expiry rules and query semantics.
- Do not wrap writes: a successful committed transaction remains authoritative if cancellation arrives after commit.

Eight deterministic tests cover Cosmos 503/cancellation races in Driver active read, promotion, expiry update, release and query-page read, plus Rider active read, promotion and release. The Driver query iterator fixture uses a disposable mock compatible with the store's `using` lifetime.
