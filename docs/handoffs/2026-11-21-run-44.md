## AUTH-API-053 implementation

The API now validates successful TriSend access JWTs using the same configured `JwtBearerOptions.TokenValidationParameters` used by the API authentication middleware. It verifies signature, issuer, audience and lifetime, requires a non-empty subject and exactly one role claim, and requires role-specific login/register tokens to match both the requested app role and `user.role`. Refresh responses receive the same cryptographic/lifetime/subject/role-shape validation.

Invalid upstream tokens produce a generic 502 and are revoked only when the token is safe token68 and at most 16 KiB. Role mismatch produces 403 and attempts revocation. Malformed or oversized tokens are never placed in an outbound Authorization header. No credential values are logged or echoed.
