## Work completed

- Added `AllowSubjectlessPrincipalMetadata` as an explicit opt-in for authenticated endpoints that deliberately use server-IP rate-limit fallback.
- Added middleware requiring a canonical `sub` for authenticated `/api/v1` and `/hubs/rides` endpoints. Public `IAllowAnonymous` auth endpoints are unaffected.
- Marked only the `/api/v1/assistance` group for subjectless fallback. It uses the server-observed remote IP, not arbitrary forwarded-for input.
- Added regressions proving a subjectless UnionManager with a valid `unionId` cannot read Union member data or approve a selfie, and cannot create reservation/profile/audit side effects.
- Extended auth tests so a subjectless token cannot call `GET /api/v1/auth/me` or trigger TriSend; a stale subjectless bearer does not block public demo-session issuance.
- Added a SignalR negotiate regression proving query-string access tokens without a subject are rejected before hub negotiation.
- Added a subjectless AI assistance test proving the explicitly marked route remains available but is rate-limited by IP.
