## Run 117 engineering changes

Audit finding: read-only Cosmos operations in support-request canonical conflict readback, queue eligibility/audit query pages, queue leave/rotation point reads and queue-audit event readback could leak a provider error when caller cancellation raced a failed await.

Implemented:
- `CosmosSupportRequestStore`: apply `CosmosReadResponseGuard.AwaitWithCancellationPrecedenceAsync` to canonical readback after create conflict.
- `CosmosQueueStore`: apply the guard to eligible query pages, audit query pages, remove, move-to-back and move-to-back-once point reads.
- `CosmosQueueAuditEventStore`: apply the guard to canonical event point readback.
- Preserve 404/412 mapping, resource identity checks, ETag conditions, query semantics and all durable write/commit behavior. No route/schema/fare/dispatch ranking changes.

Seven deterministic tests were added:
- `CanonicalReadCancellationTakesPrecedenceOverOtherProviderFailure`
- `GetEligibleCancellationTakesPrecedenceOverQueryProviderFailure`
- `GetAuditEventsCancellationTakesPrecedenceOverQueryProviderFailure`
- `RemoveCancellationTakesPrecedenceOverPointReadProviderFailure`
- `MoveToBackCancellationTakesPrecedenceOverPointReadProviderFailure`
- `MoveToBackOnceCancellationTakesPrecedenceOverPointReadProviderFailure`
- `ReadProviderFailureDoesNotHideCancellation`
