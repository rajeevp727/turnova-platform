## Engineering completed this run

Cosmos Driver/Rider reservation stores previously could return local early outcomes after a point read without rechecking cancellation: expired acquisition conflict, already-permanent promotion success, unchanged-expiry success, mismatched-RideId release false, and not-found translations. The in-memory adapters already observed cancellation at entry.

The Cosmos adapters now:
- check cancellation before local validation/expiry early returns and retry loops;
- recheck immediately after awaited point reads before ownership, expiry, idempotency or missing-record decisions;
- check after unsuccessful transactional batch responses before conflict/retry handling;
- observe cancellation while translating Cosmos 404 outcomes to false/null;
- check batched Driver reservation reads during chunk processing and before return;
- preserve successful transactional commits as authoritative and do not throw cancellation after a durable write has succeeded.

Nine strict-Moq tests were added in `CosmosReservationCancellationTests`, covering Driver and Rider acquisition, promotion, expiry, release and active reads. No queue ranking, assignment, fare, dispatch or Rider selection behavior changed.
