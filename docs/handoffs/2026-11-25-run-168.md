## Work completed

The API JWT bearer boundary now rejects ambiguous role representations. Previously, `OnTokenValidated` counted only `role`, so a token could contain a canonical role plus a competing `roles` or `ClaimTypes.Role` URI claim. The validator now treats all three claim types as role representations and accepts exactly one canonical `role` claim whose value is one of Rider, Driver, UnionManager or non-privileged Ops.

Added `AuthApiIntegrationTests.AlternateRoleClaimAliasesAreRejectedAlongsideCanonicalRole`, with two deterministic cases:
- canonical `role=Rider` plus `roles=Rider`;
- canonical `role=Rider` plus the `ClaimTypes.Role` URI alias.

Both assert a generic 401, no-store/no-cache headers and no JWT error detail. Existing Ops admin-key separation is unchanged.
