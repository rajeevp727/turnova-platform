## Work completed

The API audit found that the four public Cosmos identity operations validated inputs before checking an already-cancelled request token. This mattered when an identity Container was injected because `GetContainerAsync` could return the injected Container without observing cancellation.

The implementation now checks cancellation at the beginning of:

- `RegisterAsync`
- `LoginAsync`
- `RefreshAsync`
- `LogoutAsync`

Register/Login null request objects and Logout null principal fail fast with `ArgumentNullException` after cancellation is checked. Refresh retains its existing 400 response for a null/blank refresh token when the request is not cancelled. No persistence, token rotation, session revocation or registration batch starts for a pre-cancelled request. Successful committed registration remains authoritative; no cancellation check was added after commit.

Seven deterministic tests were added:

- `RegisterHonorsPreCancelledTokenBeforeRequestValidation`
- `RegisterRejectsNullRequestBeforeCallingCosmos`
- `LoginHonorsPreCancelledTokenBeforeRequestValidation`
- `LoginRejectsNullRequestBeforeCallingCosmos`
- `RefreshHonorsPreCancelledTokenBeforeMissingRequestValidation`
- `LogoutHonorsPreCancelledTokenBeforePrincipalValidation`
- `LogoutRejectsNullPrincipalBeforeCallingCosmos`
