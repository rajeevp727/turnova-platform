## Implementation

The only Operations Union assignment writer used `UpsertItemAsync`; the in-memory adapter used an unconditional dictionary indexer. The durable per-Driver reservation lease serializes the normal transfer flow, but a request that outlives the temporary lease could still overwrite a newer assignment.

The API now:
1. Uses `CreateItemAsync` when no previous assignment was observed; duplicate create returns conflict.
2. For an existing assignment, point-reads current state, compares the complete value snapshot with the caller's expected snapshot, requires a nonblank ETag from that exact read, and conditionally replaces with `IfMatchEtag`.
3. Treats missing records and 409/412 conditional-write races as HTTP 409; it never falls back to unconditional upsert.
4. Uses `ConcurrentDictionary.TryAdd`/`TryUpdate` for the in-memory adapter.
5. Retains the caller's original expected snapshot across audit-snapshot recovery. If audit recovery changes the assignment snapshot, the transfer conflicts rather than rebasing onto a newer assignment; the caller can retry with fresh state.

No API request/response schema or persisted data model changed.
