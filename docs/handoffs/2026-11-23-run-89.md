## Engineering completed

The audit found cancellation gaps in migration bootstrap and lease orchestration:

1. `CosmosMigrationRunner.RunAsync` did not check a pre-cancelled token before database creation or recheck after successful database/history/lock-container creation.
2. Cancellation immediately after a committed lease acquisition could be missed when the migration list was empty.
3. `IsAppliedAsync` returned `true` after a successful point read or `false` after 404 without a post-await cancellation check.
4. `CosmosMigrationLeaseCoordinator` relied on stores to throw cancellation after a failed create/read/lost ETag replacement; cancellation during a lost renewal race could be surfaced as lease-lost.

The runner now checks cancellation before bootstrap, after each awaited bootstrap operation, inside the release-protected block immediately after lease acquisition, and before/after history point reads and 404 translation. The coordinator checks cancellation before acquisition/renewal store work and after failed create/read/lost replacement results. Successful committed lease create/replace results are still returned so the latest ETag can be released; no lease or migration persistence semantics were weakened.
