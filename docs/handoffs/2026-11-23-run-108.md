## Newly merged native-auth API audit

PR #207 added `CosmosIdentityService` and removed demo/TriSend authentication from main. The main CI success is useful build evidence, but API auth implementation is not yet acceptance-ready. The following safe engineering gaps remain in the current main code and must be handled in the API phase:

1. Registration creates the email reservation and user document in two independent Cosmos writes. If the request is cancelled after reservation creation, cleanup uses the already-cancelled request token and can leave a permanent stale reservation. Prefer a same-partition transactional batch or bounded cleanup that preserves cancellation semantics.
2. Login, refresh and logout replace identity documents without ETag `IfMatchEtag`. Concurrent login/refresh/logout can overwrite refresh-token state; two requests can both accept one old refresh token and return success. Add conditional writes and deterministic race tests.
3. Current `AuthApiIntegrationTests` cover storage-unavailable and validation paths, but not successful Cosmos registration, password verification, login, refresh rotation, logout revocation, duplicate-email contention or rollback/concurrency cases. Add deterministic Cosmos SDK contract/integration tests.
4. Public register/login/refresh routes have no auth-specific rate-limit policy. Add a bounded privacy-safe policy and document trusted-proxy/IP assumptions before public enablement.
5. Existing TriSend accounts are not automatically migrated. Keep that as an explicit owner/operations migration decision; do not claim account migration is complete.
