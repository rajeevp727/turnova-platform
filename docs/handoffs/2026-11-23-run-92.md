## Current item: COSMOS-STORE-016..018

The queue and reservation adapters use Cosmos transactional batches to commit the state record and append-only audit event together. Once a successful batch response is received, cancellation arriving immediately afterwards must not change the operation's successful result or encourage a duplicate retry.

Three deterministic tests were added:
1. `CosmosQueueCancellationTests.QueueJoinRemainsSuccessfulWhenCancellationArrivesAfterAtomicCommit`.
2. `CosmosReservationCancellationTests.DriverAcquireRemainsSuccessfulWhenCancellationArrivesAfterAtomicCommit`.
3. `CosmosReservationCancellationTests.RiderAcquireRemainsSuccessfulWhenCancellationArrivesAfterAtomicCommit`.

Each cancels the token inside a successful transactional-batch response callback and verifies the operation still succeeds with both state and audit documents submitted in the same batch. These are test-only changes; no production runtime code changed.
