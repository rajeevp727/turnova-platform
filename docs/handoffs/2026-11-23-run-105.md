## Current item and engineering change

Hardened two Cosmos canonical point-read paths that previously checked only for a non-null resource:

1. `CosmosQueueAuditEventStore.ReadAsync` now requires the returned `EventId` and `ZoneServiceKey` to match the requested event ID and partition key.
2. `CosmosSupportRequestStore.CreateOrGetAsync` now requires the canonical resource returned after a create conflict to match both the attempted `Id` and `ReporterId`. A malformed or cross-reporter result throws a storage-integrity exception instead of being surfaced as a replay/conflict result.

Four deterministic theory cases cover wrong queue-audit EventId, wrong queue-audit partition, wrong support request Id and wrong support ReporterId. No API route, schema, reservation, ride-state, FIFO or customer-facing dispatch behavior changed.
