## Work completed

The logout endpoint previously forwarded any parseable `Authorization` scheme to TriSend, although the MVP contract only permits Bearer credentials. The route now rejects a supplied malformed, empty or non-Bearer authorization value locally with HTTP 400, no-store/no-cache headers, and no upstream request. A supplied Bearer value—including an expired or invalid token—is still forwarded unchanged so TriSend remains responsible for revocation validity. Requests without an Authorization header retain the prior best-effort behavior.
