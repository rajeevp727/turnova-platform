## Engineering change

CosmosMigrationRunner previously used the History create response's Container directly and discarded the Lock create response without validating either resource identity.

Both bootstrap responses are now validated before lease acquisition or migration execution:

- Resource must be non-null.
- Resource.Id must exactly match MigrationHistory or MigrationLocks respectively.
- Resource.PartitionKeyPath must be exactly /id.
- Container handle must be non-null.

Eight deterministic cases cover null resource, mismatched ID, mismatched partition-key path and missing handle for both containers. Existing cancellation-after-create tests now use valid response metadata and continue to prove that cancellation after History creation prevents Lock creation, and cancellation after Lock creation prevents lease acquisition.
