## Audit finding and implementation

`CosmosRideOfferStore` read-only point reads, query-page reads and query-result hydration could leak a provider failure (for example, Cosmos 503) if request cancellation raced the failed await. Existing post-success cancellation checks did not cover the provider-failure branch.

Added `CosmosReadResponseGuard.AwaitWithCancellationPrecedenceAsync`:
- checks cancellation before the provider operation;
- checks cancellation after successful completion;
- if the provider throws, checks the caller token before rethrowing the provider exception;
- preserves the original provider exception when cancellation was not requested.

Applied it to:
- `GetByRideAsync`;
- `GetPendingForDriverAsync` query pages;
- `GetExpiredAsync` query pages and hydrated point reads;
- `GetPendingNotificationsAsync` query pages and hydrated point reads.

Existing 404 mapping, resource validation, ETag propagation, query semantics and successful read results are unchanged. No write/commit path is wrapped or reclassified; successful durable writes remain authoritative.
