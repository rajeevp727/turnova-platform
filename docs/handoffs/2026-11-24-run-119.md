## Run 119 implementation

Rider active-booking RequestHash is part of the persisted same-ride idempotency identity. The Cosmos resource guard previously checked expected RiderId and non-empty RideId but did not reject blank/whitespace persisted RequestHash. Both acquisition stores also accepted a blank hash supplied by an internal caller.

Implemented:
- `CosmosRiderActiveBookingReservationStore.RequireResource` rejects blank/whitespace RequestHash.
- Cosmos and in-memory `TryAcquireAsync` reject blank/whitespace RequestHash before writing reservation or audit state.
- Added `RiderActiveReadRejectsBlankRequestHash`, `CosmosAcquireRejectsBlankRequestHashBeforeCallingCosmos` and `InMemoryAcquireRejectsBlankRequestHashBeforeStoringReservation`.
- Tests assert fail-closed read behavior, zero Cosmos calls for invalid input, and no in-memory reservation/audit mutation.
- Valid same-ride replay, ETag conditions, transactional batches, audit events and expiry semantics are unchanged.
