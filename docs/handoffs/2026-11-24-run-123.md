## Run 123 engineering change

Audit found that both `CosmosRiderActiveBookingReservationStore.TryAcquireAsync` and `InMemoryRiderActiveBookingReservationStore.TryAcquireAsync` validated a null reservation before checking the caller's cancellation token. A pre-cancelled/null call therefore produced `ArgumentNullException` instead of `OperationCanceledException`.

Both methods now check cancellation before null-reservation validation. Valid RiderId/RideId/RequestHash checks, transactional reservation+audit writes, ETag, expiry, idempotency and in-memory locking behavior are unchanged.

Four deterministic tests cover:
1. Cosmos pre-cancelled + null → `OperationCanceledException`, no Cosmos call.
2. In-memory pre-cancelled + null → `OperationCanceledException`, no reservation/audit mutation.
3. Cosmos uncancelled + null → `ArgumentNullException`, no Cosmos call.
4. In-memory uncancelled + null → `ArgumentNullException`, no reservation/audit mutation.
