## Work completed

The API persistence audit found that Cosmos database and container bootstrap create operations were directly awaited. A provider task failing concurrently with caller cancellation could expose the provider exception rather than the caller's cancellation.

Added `CosmosReadResponseGuard.AwaitCommittedWriteWithCancellationPrecedenceAsync`. It:
- checks pre-cancellation before calling the provider;
- preserves the exact provider exception when no caller cancellation occurred;
- gives caller cancellation precedence when the provider task fails during cancellation;
- does not retroactively convert a successful committed write into cancellation.

Applied to support-container creation, migration database creation, and MigrationHistory/Lock container creation. Eight deterministic Cosmos SDK-mock tests cover cancellation and non-cancellation provider failures at each path.
